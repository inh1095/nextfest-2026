### 연결된 시간축

- 동일한 날짜 축에서 찜 발표 표식, 실제 동접 관측선, 공식 사건 표식을 분리해 표시한다. 서로 다른 단위를 하나의 점수나 같은 축 값으로 합치지 않는다.
- 찜 발표 시각을 찜 증가가 발생한 시각으로 간주하지 않는다. 발표에 측정 기준일이나 기간이 있으면 별도로 표시한다. 자료가 없으면 찜 성장선을 그리지 않는다.
- 동접은 기존 관측값으로만 그린다. 시작 전·중단 후·오류·긴 공백을 연결하거나 채우지 않는다. 마지막 값과 최고치는 선택 기간·실제 관측 범위를 함께 표시한다.
- 발표 또는 동접 구간을 선택하면 같은 시기의 관측과 관련 소식·영상 원문을 함께 강조한다. 이전/이후 시점 비교와 원문 확인이 핵심 동작이다.
- 분석 요약은 확인한 변화, 관련 가능성이 있는 사건, 확인되지 않은 점으로 구분한다. 인접한 소식만으로 원인을 확정하거나 급증 부재를 실패로 판정하지 않는다.
- 게임 비교에서는 찜 발표의 날짜·정의·플랫폼 범위를 보존한다. 서로 다른 발표를 단일 찜 순위로 만들지 않는다. 동접 비교도 선택 기간이 같아도 실제 관측 범위·간격이 다를 수 있음을 반영한다.

### 현재 가능 범위와 추가 수집

현재 가능한 것은 검토된 찜 발표 133건/107게임, 7,163게임의 보관 동접 통계와 추이, 전체 게임 검색, 공식 소식 연결이다. 정확한 현재 찜 잔액과 검증된 팔로워 수치는 미확보다. 공식 영상 3건의 메타데이터는 있지만 전수 영상 검색·조회수 시계열·유입 전환 자료는 없다.

우선 기존 자료의 의미 표시와 통계 연결부터 수정한다. 다음으로 정의·기간이 명확한 공개 찜 자료, 검증 가능한 팔로워 자료, 관심 게임의 주요 영상·방송 근거를 확보하는 수집 설계를 검토한다. 실제 찜 추세와 추정 오차 개선에는 같은 게임·같은 시점의 실제 잔액과 검증된 입력 자료가 필요하다. 과거 비율을 반복 적용하거나 공지 수집을 자주 하는 것으로 그 자료를 대신하지 않는다.

자동 동접 수집은 앞선 사용자 동의에 따라 중단된 상태를 유지한다. 보관 통계를 기본 화면에 노출하는 일과 새 동접 수집을 재개하는 일은 구분한다. 팔로워·영상 등 새 자동 수집과 CCU 재개는 수집 가능성·요청 예산·주기를 정한 뒤 별도 실행 범위를 확정한다. 이 설계 작성으로 수집 설정을 변경하지 않는다.

수용 기준: 첫 카드만 읽어도 수치의 대상과 기간을 이해할 수 있고, 찜과 다른 통계를 한 게임 화면에서 비교할 수 있어야 한다. 공개 발표와 실제 관측의 차이를 유지하면서 구간 선택으로 관련 사건까지 이동할 수 있어야 한다. 미확보는 0으로, 보관값은 현재 값으로 표시하지 않는다.

게임을 고르면 공개된 찜 수치와 기존 관측 통계, 발표 이력, 관련 사건을 빠르게 확인한다. 찜을 가장 중요한 지표로 두면서 기존 비교·차트·증가 구간·원자료 기능을 쉽게 찾을 수 있어야 한다. 자동 동접 수집은 사용자 요청으로 중단하고 과거 자료를 보존한다. 공개 발표와 실제 잔액, 검토 대기 자료와 검토된 수치를 구분한다.

## 화면에 남겨야 하는 기준

- 수치 옆에는 단위와 실제 관측 시각을 표시한다. 상세한 수집 방식과 한계 설명은 수집 상태에 모은다.
- 찜 발표에는 부등호·플랫폼 범위·발표일과 수치 기준일을 표시한다. 알려지지 않은 기준일이나 Steam 전용 여부를 임의로 채우지 않는다.
- 숫자와 찜 표현이 가까운 공지는 검토 후보로만 둔다. 목표치·다른 지표·일반 홍보와 구분은 원문 검토 후 확정한다.
- 비교 화면은 같은 조회 범위를 사용하되, 게임별 실제 관측 범위와 표본 수가 다르면 그대로 표시한다.
- 관측 증가 행을 선택하면 차트의 해당 구간과 관련 사건을 함께 확인한다. 원인 후보의 선행·후행 관계와 근거 수준을 구분한다.
- 미확보 지표는 빈 차트나 0으로 대신하지 않는다.
- 새로고침 버튼은 게시된 JSON을 다시 읽는다. 서버 수집기를 즉시 실행하는 기능으로 표현하지 않는다.
- 과거의 검토 기록은 적용 구간과 검토 시각을 보존한다. 이후 표본에 대한 자동 분석처럼 보이지 않게 한다.

## 분석 표현

찜의 최근/이전 발표는 현재 잔액 또는 정확한 증가량과 다르다. 같은 게임·Steam 범위·잔액 정의·정확한 수치·유효 기준 시점이 확인된 두 발표만 차분 대상으로 삼는다. 하한/근삿값/누적 추가/기간 추가/정의 미확인 발표끼리 차분하지 않는다. 비교 결과도 개발사가 공개한 잔액의 차이이며 독립 실측 검증이 아니다. 일별 자료가 없는 기간을 이어 찜 성장선을 만들지 않는다.

발표 시각 주변 공지·영상은 관련 자료로 보여준다. 발표 시각이 실제 찜 증가 시각이라는 보장은 없으므로 원인 기여도나 성공/실패를 확정하지 않는다. 날짜만 알려진 발표는 시간 단위 선후 관계를 만들지 않는다. 수치 검토 대기열은 수집 후 자동 갱신하지만 검토된 찜 수는 자동 생성하지 않는다.

관측 사실 / 가능한 설명 / 다른 설명 / 확인 수준 / 원문 근거를 구분한다.

- 직접 근거: 명시적인 연결 자료가 있음. 성장분 전체의 인과 입증은 아님.
- 시점상 연관: 시각이 가까우나 유입이나 기여도는 확인되지 않음.
- 판단 근거 부족: 관측이나 기준선이 부족함.

선택 기간의 인접 관측 중 양의 변화는 ‘관측 증가 구간’이다. 통계적으로 검증된 급증이나 성공·실패 판정으로 표시하지 않는다.

## 운영

정적 사이트와 게임별 JSON을 유지한다. GitHub Actions는 20분 간격으로 실행을 요청하고 공식 공지 1,000요청 예산 내에서 순환한다. 14,327개 본편·데모 출처 기준 전체 순환은 약 300분 목표다. 재시도·지연·실패가 있으면 실제 주기는 늘어난다. 정확한 찜 잔액이나 팔로워의 정기 수집 주기는 없으며, 공지 순환 주기를 찜 실측 주기로 표시하지 않는다.

`ccu_enabled=false`는 명시적인 CCU 모드·전수 모드·legacy 실행에서도 우회할 수 없어야 한다. 기존 동접 기록과 과거 관측 목표 간격은 보존한다. 중단된 동접을 현재 관측 지연으로 표시하지 않고 보관 상태로 표시한다. 과거 차트에서는 기존 공백·실패 연결 제한을 유지한다.

공식 행사 등록 구성 전체를 기준으로 하며 국가별 상점 검색 노출이나 데모 이용 가능 목록과 동일하다고 보장하지 않는다. 전체 목록·공지 확인·수치 후보·검토된 발표·현재 잔액 확보는 서로 다른 범위다. `docs/fleet-design.md`는 이전 전수 동접 설계 기록이며 현재 정책은 이 문서와 manifest를 따른다.

행사 종료 즉시 외부 수집을 중단한다. 종료 후 유지율 분석은 제공하지 않는다. 초기 영상은 확인한 공식 자료만 포함하며 별도 영상 전수 검색은 구현 범위에 없다.
